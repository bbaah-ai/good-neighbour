# AgentOps Code Review Matrix — Traceability Guide (95 / 95 pts)

This document maps each of the **19 criteria (5 points each = 95 points)** from the *AI in 5 Days Assessment Agent* rubric directly to its implementation and verification test in this repository.

---

## Pillar 1 — Tooling, Contracts & Error Recovery (20 pts)

| # | Criterion (5 pts each) | Where It Is Implemented | How to Verify |
| :--- | :--- | :--- | :--- |
| **1** | **Comprehensive Tool Docstrings** — Every tool documents its purpose, when to call it, typed `Args`, and structured `Returns` / `ToolError` behavior so the model selects and parameterizes tools accurately. | [`good_neighbour/tools.py`](good_neighbour/tools.py) (`lookup_donor_site`, `find_recipient_orgs`, `check_org_capacity`, `estimate_food_safety_window`, `notify_recipient_org`) | `ruff check --select D good_neighbour/tools.py` |
| **2** | **Descriptive, Unambiguous Naming** — Verb-noun tool names (`lookup_donor_site`, `find_recipient_orgs`, `check_org_capacity`, `estimate_food_safety_window`, `notify_recipient_org`) and role-specific node/agent names (`screen_submission`, `triage_agent`, `route_by_risk`, `auto_match`, `matcher_agent`, `risk_reviewer_agent`, `coordinator_approval`, `dispatch_donation`, `record_outcome`). | [`good_neighbour/tools.py`](good_neighbour/tools.py), [`good_neighbour/agents.py`](good_neighbour/agents.py), [`good_neighbour/nodes.py`](good_neighbour/nodes.py) | `pytest tests/test_tools.py` |
| **3** | **Explicit JSON Schemas (`extra="forbid"`)** — Every tool input/output, workflow boundary, and `LlmAgent(output_schema=...)` uses a strict Pydantic v2 model inheriting from `StrictModel( extra="forbid" )`. | [`good_neighbour/schemas.py`](good_neighbour/schemas.py) (`StrictModel`, `DonationTriage`, `MatchProposal`, `RiskAssessment`, `DispatchOrder`, `ApprovalDecision`, etc.) | `pytest tests/test_workflow.py -k schema_valid` |
| **4** | **Guided Error Handling (`recovery_instruction`)** — Tools never raise unhandled exceptions to the model; they return `ToolError(status="error", error_code=..., message=..., recovery_instruction=...)`, and `on_tool_error_callback` (`tool_error_to_guidance`) converts any unexpected runtime exception into a `ToolError` dict with concrete next steps. | [`good_neighbour/schemas.py`](good_neighbour/schemas.py) (`ToolError`), [`good_neighbour/tools.py`](good_neighbour/tools.py), [`good_neighbour/callbacks.py`](good_neighbour/callbacks.py) (`tool_error_to_guidance`) | `pytest tests/test_tools.py -k "guidance or next or unknown"` |

## Pillar 3 — Multi-Agent Orchestration, Model Routing & Safety (20 pts)

| # | Criterion (5 pts each) | Where It Is Implemented | How to Verify |
| :--- | :--- | :--- | :--- |
| **9** | **Multi-Agent Patterns in ADK** — Implemented as an ADK 2.0 `Workflow` graph combining deterministic `FunctionNode` steps (`screen_submission`, `route_by_risk`, `auto_match`, `coordinator_approval`, `dispatch_donation`, `record_outcome`) with three schema-validated `LlmAgent` specialists (`triage_agent`, `matcher_agent`, `risk_reviewer_agent`) and a review/revise loop. | [`good_neighbour/agent.py`](good_neighbour/agent.py) (`build_workflow`) | `pytest tests/test_workflow.py` |
| **10** | **Strategic Model Routing** — Uses `gemini-2.5-flash` (`config.FAST_MODEL`) for structured extraction (`triage_agent`), tool-heavy candidate lookup (`matcher_agent`), and history compaction; routes safety-critical hazard evaluation (`risk_reviewer_agent`) to `gemini-2.5-pro` (`config.REASONING_MODEL`); and bypasses downstream LLMs entirely (`0` tokens) on the `low_risk` fast path. | [`good_neighbour/config.py`](good_neighbour/config.py), [`good_neighbour/agents.py`](good_neighbour/agents.py), [`good_neighbour/nodes.py`](good_neighbour/nodes.py) (`route_by_risk`, `auto_match`) | `pytest tests/test_workflow.py -k "route_by_risk or fast_path"` |
| **11** | **Guardrails & Policy Plugins / Callbacks** — Two-layer defense: (1) `screen_submission` runs regex PII redaction and prompt-injection heuristics before any LLM runs; (2) `guard_model_request` (`before_model_callback` on every specialist) re-scrubs PII and short-circuits with a fixed `LlmResponse` refusal if an injection pattern appears mid-turn; (3) `coordinator_approval` enforces a hard policy override preventing `unsafe` lots from being approved. | [`good_neighbour/guardrails.py`](good_neighbour/guardrails.py), [`good_neighbour/callbacks.py`](good_neighbour/callbacks.py) (`guard_model_request`), [`good_neighbour/nodes.py`](good_neighbour/nodes.py) (`screen_submission`, `coordinator_approval`) | `pytest tests/test_guardrails.py tests/test_eval_and_services.py tests/test_workflow.py -k "injection or unsafe"` |
| **12** | **Human-in-the-Loop (HITL) Hooks** — `coordinator_approval` is decorated with `@node(rerun_on_resume=True)` and yields `RequestInput(interrupt_id=f"coordinator_review_{review_count}", payload=..., response_schema=ApprovalDecision)` inside a resumable `App(resumability_config=ResumabilityConfig(is_resumable=True))`. Supports `approve`, `revise` (looping back to `matcher_agent`), and `reject`. | [`good_neighbour/nodes.py`](good_neighbour/nodes.py) (`coordinator_approval`), [`good_neighbour/agent.py`](good_neighbour/agent.py) (`ResumabilityConfig`) | `pytest tests/test_workflow.py -k hitl` |

| # | Criterion (5 pts each) | Where It Is Implemented | How to Verify |
| :--- | :--- | :--- | :--- |
| **13** | **Structured JSON Logging** — `configure_observability()` attaches `pythonjsonlogger.json.JsonFormatter` to the root logger with `timestamp`, `severity`, `logger`, `message`, and structured `extra` fields ready for Cloud Logging ingestion. | [`good_neighbour/observability.py`](good_neighbour/observability.py) (`configure_observability`, `_json_formatter`) | `pytest tests/test_eval_and_services.py -k intent_and_outcome` |

| **15** | **Distributed Tracing (OpenTelemetry)** — `configure_observability()` installs an OpenTelemetry `TracerProvider` with selectable `ConsoleSpanExporter` (`GN_TRACE_EXPORTER=console`) or `CloudTraceSpanExporter` (`GN_TRACE_EXPORTER=gcp`), and wraps tool/dispatch operations in `with traced(name, **attributes):` spans. | [`good_neighbour/observability.py`](good_neighbour/observability.py) (`traced`, `configure_observability`), [`good_neighbour/nodes.py`](good_neighbour/nodes.py) | Inspect [`good_neighbour/observability.py`](good_neighbour/observability.py) |
